# The Scope of a Pass — executed workflow study W2

Anonymous Stage 1 review object. Synthetic organizational research tasks only. The current proposal contains 1,789 words including numbered headings, with references additional.

## What was actually run

Twelve new task instances across four mathematical structures; two requested model configurations (GPT-6 Astra and GPT-6.1 Sol, high reasoning effort); 24 model-generated source analyses; 48 numerical checker contexts; six downstream information policies; 144 receiver episodes; 270 distinct logical model calls. Programs execute in a restricted arithmetic process, reviewers can propose replacement code, and interpreters can request one archived design record.

The comparison includes a shared-transcript single researcher, complete delegated records, analyst-selected compact records and three deliberately dropped-design conditions. The last three compare general pass, scoped numerical pass and the same caution as a separate reminder. Upstream artifacts are shared for matched comparisons. This is not 144 independent source studies, and call opportunities do not equalize token budgets.

## Findings and preserved scoring distinction

Both models selected the design record in every natural handoff (24/24 source selections). All 24 programs executed and all 48 reviewed numerical artifacts passed. In the deliberate-loss conditions, both models requested the design record on all nine causal questions per condition and answered the three descriptive questions without that request: 54 archive requests across the 72 stress episodes. All 144 final claim types and values were warranted by received evidence and matched the original source task. No unsupported causal claim or numerical error occurred. Stronger verification wording produced no observed improvement in those scientific outcomes or retrieval counts.

The FROZEN literal record-ID contract flagged ten citations to population_table, a field actually present in the supplied packet. The original joint-contract counts accept 134/144 and remain unchanged in results.json, episodes.csv, summary.csv and paired_contrasts.csv. A disclosed POST-RUN audit recognizes only that exact received field name, retains every original flag, and reports scientific correctness separately in reporting_results.json, scientific_summary.csv, scientific_paired_contrasts.csv and citation_audit.csv. No unknown record ID or missing causal premise is forgiven. Do not interpret the literal identifier differences as a scientific message effect.

No model outputs were edited, discarded, regenerated after inspection, or selected for favorable results. The ten identifier-contract flags, the prior nulls and the earlier weaker-model failure are preserved.

## One-command offline reproduction

Python 3.10+ and its standard library. Extract the ENTIRE ZIP and double-click RUN_ME.cmd on Windows, or run from the package root:

    python -B reproduce.py --out ../guardlab_workflow_reproduction_01

Use a new output directory. The command verifies release/frozen hashes, runs sixteen frozen workflow tests and four post-run citation-audit tests, checks 24 information regimes, reconstructs 48 numerical artifacts and regrades all 144 episodes. It preserves and reproduces both strict and audited scores. It also extracts the exact historical release and runs its twenty tests and separate 48-decision and twelve-decision pilot reproductions. It makes ZERO model or network calls and uses no GPU or private data.

The default launcher creates a new run under LOCAL_REPRODUCTION_OUTPUTS when drive D exists, or a temporary-directory subfolder otherwise. Fixed software versions are recorded in BUILD_ENVIRONMENT.json; cross-version presentation can vary. Scientific tables are recomputed from saved records. Repeating the model generation itself requires access and may produce different outputs.

## New runs and limitations

The frozen adapters preserve the exact client route used here, including task-local Windows CLI and scratch paths. They are provenance, not generic installation utilities. For a new study, make a separate working copy, configure the client, select and freeze NEW task settings and output directories, record access and budgets, and retain the old artifacts. Do not silently edit the frozen protocol or overwrite raw run folders.

The complete review object exposes keys and witnesses. Evaluated models must receive only their assigned text and declared calculator/archive actions. File separation and hashes are not an operating-system security boundary. The actual model calls prohibited native tools; logs contain no native tool calls. The restricted program process cannot read files or access the network.

These exact-population tasks do not evaluate finite-sample uncertainty, real-world exchangeability, arbitrary papers, construct validity or open-ended scientific discovery. Short labeled records and a one-action archive make recovery unusually explicit. The models share a provider; four mathematical structures remain four regardless of seed count. There has been no independent human methodological audit. A complete proposal and executed prototype do not establish a general model ranking or a field-changing empirical result.

All data and code in this review object are intended for inspection. The authors should select a final distribution license and hosting arrangement before public release. No upload or journal submission is performed by these commands.
